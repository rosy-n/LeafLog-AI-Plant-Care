# 농작물 병해충 데이터 RAG 통합 계획 (보류 — 미구현)

> 상태: **설계만 확정, 코드 미반영.** 로컬 맥북 디스크 부족(228GB 중 여유 7.6GB)으로 다운로드조차 못 한 상태에서 중단.
> RunPod도 쓰지 않기로 함 — "우리 프로젝트의 클라우드"가 정해지면 그때 처음부터 이 문서 기준으로 진행.

## 배경

`ai/diagnosis`의 실내식물 병해충 이미지는 200장뿐이라, 대규모 농작물 병해충 데이터(AI-hub)를 섞어서
검색 커버리지를 늘리고 싶음. 단, 농작물과 실내식물은 병징이 다를 수 있어서 동일 가중치로 섞으면 안 됨.

## 다운로드 범위 (확정)

### 525번 (메인)

**받을 것**: 작물별 `병해.zip` + `생리장해.zip`, Training(TS) + Validation(VS) 둘 다
**받지 않을 것**:
- `정상.zip` — 무병징 대조군, 우리 목적(증상 검색)엔 불필요, 용량만 큼
- `작물보호제처리반응.zip` — 농약 살포 후 반응 연구용, 병해충 진단과 무관
- `환경센서/` — 이미지 아닌 센서 로그, CLIP 임베딩 대상 아님

### 153번 (보강)

**받을 것**: 위 매핑 표에서 ✅인 9개 클래스(흰가루병 5작물 + 노균병 3작물 + 잿빛곰팡이병 1 + 탄저병 1)의 **질병 원본** 이미지만
**받지 않을 것**:
- 정상 이미지 (204,909장) — 전체 스킵
- 증강 이미지 (약 20만 장) — 원본만으로 충분, 증강본은 CLIP 임베딩 다양성에 실질적 이득 없이 용량만 차지
- 바이러스성 3종, 매핑 보류된 잎곰팡이병/점무늬병/균핵병 — 위 매핑 표의 ❌ 전부 제외

Train/Validation을 둘 다 받는 이유: CLIP은 파인튜닝하지 않고 그대로 쓰므로 과적합/데이터 누수 개념이
적용되지 않음. 대신 검색 품질 평가는 **실내식물 200장 중 일부(예: 20장)를 인덱스에서 제외하고
쿼리 전용 홀드아웃으로 남겨서** 진행하기로 함 (아래 "검증 계획" 참고).

## suspected_cause 목록 확장 (14 → 18, 아직 `config/cause_codes.json` 미반영)

기존 14개 확정 목록에 아래 4개 추가하기로 함:

- **노균병** (병해) — 관상식물에도 흔한 곰팡이병
- **잿빛곰팡이병** (병해, Botrytis) — 숙주 범위가 매우 넓어 실내식물에도 흔함
- **다량원소 결핍** (생리장해) — 질소/인/칼륨 결핍, 작물/관엽 공통 증상
- **냉해피해** (생리장해) — 창가 온도차로 인한 냉해, 실내식물에도 실제 발생

기존 14개 중 AI-hub와 이름이 겹치는 것: 흰가루병, 탄저병, 일소현상(AI-hub 라벨명은 "일소").

**제외하기로 한 AI-hub 클래스** (열매/모종 특이적이라 관엽 식물 진단과 안 맞음):
- 열과 (결실 작물 전용)
- 축과병 (포도 특이 생리장해)
- 모잘록병 (발아 직후 모종 전용)
- 칼슘결핍 (AI-hub 라벨이 과일 배꼽썩음병 기준 — 잎에 나타나는 칼슘결핍과 병징이 다름)

## 검색 아키텍처 (완전 분리 컬렉션 대신 이 구조로 확정)

- 컬렉션은 하나로 유지, payload에 `domain` 필드 추가 (`"houseplant"` / `"crop"`)
- `03_search_similar.py`의 기존 species 우선순위 fallback 패턴을 domain에도 적용하는 tiered 검색:
  1. houseplant + species 일치
  2. houseplant 전체 (species 무시)
  3. crop 전체 — 원인(suspected_cause)별 신뢰도 가중치로 score 보정 후 남은 자리만 채움
- crop 도메인 point ID는 houseplant의 `image_id`(int)와 충돌 방지를 위해 `domain:image_id` 조합의 결정적 UUID로 부여 (구현 시 결정)

## 원인별 신뢰도 가중치 (초안, 실측 전까지 임시값)

숙주 특이성이 낮을수록(=농작물 사례를 믿을 수 있을수록) 가중치를 1에 가깝게:

- 일소현상: ~0.9 (물리적 광 손상, 숙주 특이성 거의 없음)
- 흰가루병: ~0.8 (숙주 범위 넓은 자낭균)
- 노균병 / 잿빛곰팡이병 / 다량원소 결핍 / 냉해피해: 구현 시점에 판단 필요 (TODO)
- 탄저병: ~0.65 (Colletotrichum은 숙주별 종이 다른 경우가 많음)

## 검증 계획

실내식물 200장 중 일부(예: 20장)를 인덱스에서 제외하고 쿼리 전용 홀드아웃으로 보관.
`05_eval_retrieval.py`에서 "크롭 데이터 섞기 전 vs 섞은 후" precision@k를 이 홀드아웃 쿼리로 비교해서,
실제로 검색 품질이 좋아지는지 확인한 뒤에만 프로덕션에 반영한다 (촬영 스타일 차이로 인한
CLIP 임베딩 도메인 편향 위험이 있으므로 감으로 판단하지 않음).

## 막힌 지점 (재개 시 먼저 결정할 것)

- 로컬 맥북: 디스크 여유 7.6GB뿐이라 다운로드 불가
- RunPod: 사용하지 않기로 결정
- **재개하려면 "우리 프로젝트의 클라우드" 환경이 먼저 정해져야 함** — 어떤 인스턴스/스토리지를 쓸지 결정 후, 위 계획대로 다운로드 → 필터링(불필요 클래스 삭제) → CLIP 임베딩 → Qdrant 업로드 순으로 진행
