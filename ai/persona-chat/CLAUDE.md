
# CLAUDE.md — persona_chat

이 문서는 `persona_chat` 관련 작업을 할 때 지켜야 할 규칙을 정리한 문서다.
사람이 읽는 설명은 README.md에 있고, 이 문서는 Claude Code가 작업 시 반드시
따라야 할 명령형 규칙만 담는다. 이 파일과 README.md의 역할을 섞지 않는다.

> 경로 가정: `ai/diagnosis/CLAUDE.md`와 같은 패턴으로, 이 파일은
> `ai/persona-chat/CLAUDE.md` 위치에 둔다고 가정하고 작성했다.
> 실제 브랜치의 디렉토리 구조가 다르면 경로만 맞게 옮겨서 사용한다.

---

## 1. 이 기능이 하는 일

식물 캐릭터가 사용자와 반말로 대화하며 친밀감을 형성하는 기능이다.
식물 상태/관리 이력을 직접 노출하는 상담 기능이 아니라, **친밀감 형성 목적의
캐주얼 채팅**이다. 물주기 일정과 날씨/대기질만 제한적으로 다루고,
성장 상태나 관리 기록은 페르소나 대화에서 의도적으로 배제한다.

---

## 2. 절대 규칙 (변경·완화 금지)

이 규칙들은 `test_persona.py`의 검증 로직(`detect_speech_rule_violations`,
`sanitize_speech_rule_violations`)으로 이미 코드 레벨에서 강제되고 있다.
프롬프트를 수정할 때 이 규칙과 충돌하는 방향으로 손대지 않는다.

- 모든 캐릭터 답변은 **반말만** 사용한다. 존댓말 어미(-습니다/해요/세요/이에요 등),
  -시- 높임 선어말어미(주셔/하셔/드셔 등)를 쓰지 않는다.
- 한자, 영어 단어, 이모지를 출력하지 않는다.
- 사용자 이름 뒤에 "님", "씨" 같은 높임 호칭을 붙이지 않는다.
- 답변은 **최대 2문장**으로 제한한다 (`MAX_RESPONSE_SENTENCES`).
- 확인되지 않은 날씨, 대기질, 생육 상태, 정확한 수치를 지어내지 않는다.
  제공된 상태값만 사용하고, 모르면 모른다고 짧게 답한다.
- 병해충/증상 관련 질문에 **확정 진단을 내리지 않는다**. 항상 "병해충 탭에서
  확인해보자" 식으로 안내한다.
- 물주기 관련 답변에서 "내일", "모레", "글피" 같은 **상대 날짜 표현을 모델이
  스스로 계산해서 쓰지 않는다.** 날짜 계산은 반드시 Python 쪽
  (`build_watering_schedule_status`)에서 미리 계산된 숫자를 그대로 쓴다.
  이 책임을 다시 프롬프트/LLM 쪽으로 옮기는 방향으로 리팩토링하지 않는다.
- `common.txt`에서 `[말투 예시]` 섹션은 페르소나별 톤 충돌을 막기 위해
  의도적으로 제거된 상태다. 되살리지 않는다.

## 3. 파일 구조

```
prompts/
  common.txt          # 공통 프롬프트 (모든 페르소나 공통 규칙)
  personas/
    sunshine.txt       # 햇살형
    chic.txt           # 새침형
    relaxed.txt         # 느긋형
    timid.txt           # 소심형
    sage.txt            # 현자형
    playful.txt         # 장난꾸러기형
    diligent.txt         # 성실형
    dreamer.txt          # 몽상가형
test_persona.py        # Ollama(qwen3.5:9b) 로컬 대화 테스트 CLI
```

각 persona 파일은 `[성격] [말투] [행동 원칙] [대화 예시]` 4개 섹션 구조를
따른다. 새 페르소나를 추가하거나 기존 페르소나를 수정할 때 이 구조를
유지한다.

## 4. 현재 아키텍처 결정 사항 (임의로 되돌리지 말 것)

- **날짜 계산은 Python이 담당한다.** LLM은 계산된 결과만 그대로 말한다.
  이미 구현되어 있으므로 유지한다.
- **`PLANT_CONTEXT`는 현재 하드코딩된 테스트값이다.**
  ```python
  PLANT_CONTEXT = {
      "plant_name": "몽이",
      "species_name": "몬스테라",
      "user_name": "미나",
  }
  ```
  실제 DB 연동 방식은 아직 미정이다:
  - A안: `test_persona.py`에 DB 커넥션을 직접 추가 (CLI 유지)
  - B안: `build_system_prompt`/`chat_with_ollama` 로직을 FastAPI
    엔드포인트로 옮기고 그 안에서 조회

  **어느 쪽으로 갈지 팀 논의 전까지 임의로 리팩토링하지 않는다.**
  참고용 JOIN 쿼리는 이미 `PLANT_CONTEXT` 위 주석에 있다.

- **"캐릭터 기본 대사"(character tab에 표시되는 한 줄 대사 10개)와
  `[대화 예시]`(few-shot 학습용 사용자-캐릭터 페어)는 서로 다른 파일/목적이다.**
  한 줄 대사를 few-shot 예시에 그대로 재사용하지 않는다. 반대로도 마찬가지.
- **"동숲(ACNH) 스타일" 확장 `[대화 예시]`는 방향만 합의된 상태다**
  (사용자 턴은 범용 스몰토크로 통일하고, 캐릭터 턴에 소재·개성을 담는 방식).
  **지금 단계에서 임의로 이 확장판을 추가 구현하지 않는다.** 백엔드 연동과
  UI/UX 확정이 우선이며, 이 작업은 이후 별도로 진행한다.

## 5. 작업 시 지켜야 할 것

- 새 파일/디렉토리를 만들기 전에 기존 구조를 먼저 확인한다.
- 요청받지 않은 대규모 리팩토링을 하지 않는다.
- 변경한 파일과 이유를 마지막에 요약한다.
- 브랜치/커밋 작업은 GitHub Desktop으로 하므로, 터미널 git 명령을 대신
  실행하지 않는다. 파일 수정까지만 수행한다.
- 병해충/진단 관련 문구를 작성할 때 확정형 표현("~병입니다")을 쓰지 않는다.

---

## 6. 로컬 테스트 방법

```bash
# Ollama가 실행 중이어야 한다
ollama serve

python test_persona.py --persona sunshine.txt
```

- `/reset` : 현재 대화 기억 초기화
- `/exit` : 종료
- 대화 기록은 파일/DB에 저장되지 않고 프로그램 종료 시 사라진다 (최근 5턴만 유지).
